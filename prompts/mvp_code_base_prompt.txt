The platform connects food vendors (restaurants, caterers, home chefs) with customers. Customers can browse meals, place one-time orders, or schedule recurring meal batches. Vendors manage their meals and orders. Multiple payment options are supported (Momo, Orange Money, Visa/Mastercard).

## BACKEND MICROSERVICES TO GENERATE

### 1. Meal Management Microservice (Port 8081)
- Domain: Vendor, Meal, Category, Ingredient, Order, Schedule, Rating
- Use Cases: Vendor registration, Meal CRUD, Order creation, Schedule management, Rating submission, Search/filter meals
- Infrastructure: PostgreSQL (meal_db), Kafka producer (OrderCreatedEvent), WebSocket for vendor notifications
- Controllers: VendorController, MealController, OrderController, ScheduleController, RatingController, SearchController

### 2. Payment Microservice (Port 8082)
- Domain: Cart, Invoice, Transaction, PaymentMethod, ScheduledPayment
- Use Cases: Cart management, Checkout, Payment processing (Momo/Orange/Card), Invoice generation, Recurring payments
- Infrastructure: PostgreSQL (payment_db), Kafka consumer (OrderCreatedEvent), Payment gateway integrations
- Controllers: CartController, CheckoutController, PaymentController, InvoiceController, ScheduledPaymentController

### 3. API Gateway (Port 8080)
- Spring Cloud Gateway with route configuration
- Redis for rate limiting
- JWT validation
- Circuit breaker (Resilience4j)

## CLEAN ARCHITECTURE RULES TO FOLLOW:
1. Domain layer has NO dependencies on infrastructure
2. Domain models are plain Java objects (no JPA annotations in domain)
3. Application layer orchestrates use cases
4. Infrastructure layer implements ports (repositories, event publishers)
5. Dependency inversion: infrastructure depends on domain/application, not vice versa
6. Use interfaces for repository ports
7. DTOs are separate from domain models
8. Mappers handle transformations between layers
